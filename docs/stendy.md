# Стенды и проверки вне обычного прогона

Стенд — копия сайта на выдуманных данных, отдельная от данных владельца. **Локальная версия владельца
(docker compose, тома `db-data` и `media`) — не стенд**: на ней только смотрят, ничего не сбрасывают.

## Стенды
- **CI (основной).** Каждый PR и пуш в `main` поднимает свою базу, наполняет демо-материалами и снимает страницы
  на 1440 и 390. Результат — ветка `ci-logs`: `shots/*.png`, `ci.log`, `site-preview.zip` (статическая копия сайта
  для просмотра без интернета).
- **Отдельная тестовая база для `npm run dev`.** Не трогает данные владельца:
  ```sh
  docker run -d --name academy-test-db -e POSTGRES_USER=academy -e POSTGRES_PASSWORD=academy \
    -e POSTGRES_DB=academy -p 5433:5432 postgres:17-alpine
  export DATABASE_URL=postgres://academy:academy@localhost:5433/academy PAYLOAD_SECRET=dev-only
  npm run migrate && npm run seed && npm run dev
  ```
  Адрес: http://localhost:3000 (если запущена локальная версия владельца, сначала «Остановить сайт» или `PORT=3001 npm run dev`).
  Убрать стенд: `docker rm -f academy-test-db` (это только тестовая база).
- Подключиться к базе владельца для `npm run dev` можно, только открыв порт `5432:5432` у сервиса `db` в compose:
  (`docker compose up -d db`, затем `DATABASE_URL=postgres://academy:academy@localhost:5432/academy`):
  **это та же база с данными владельца** — только с его слова и после «Сделать копию данных».

## Проверки, которые не входят в обычный прогон
- Сверка научного текста (цитаты, мнения мазхаба) с источником — вручную, по правилам `AGENTS.md`.
- Обновление поверх данных владельца: после слияния задачи с миграцией владелец делает «Сделать копию данных»,
  затем «Запустить сайт»; проверить, что его материалы на месте.
