# Как собирать урок арабского (задача 50)

Инструкция для ИИ, который переносит уроки учебника владельца «Арабский язык для чтения религиозных текстов» в курс
Тамхиди. По ней собраны уроки 1–21. Стиль уроков не менять, **схемы и пояснения не убирать** (решение владельца
31.10.2026). Рабочие скрипты и образец урока 21 лежат в `docs/arabic-lesson-tools/`. Общие правила проекта — `AGENTS.md`.

## Что присылает владелец
Владелец присылает по 2–3 урока сразу; один тред собирает 5 уроков, затем работа идёт в новом треде (решение владельца 31.10.2026). На каждый урок приходит:
1. Claude Doc (ссылка claude.ai/artifact/…). В нём словарь (таблица), грамматика кратко, предложения по группам А–Д, мини-текст, упражнения, тест и ключи.
   Читать так: `mcp__Claude_Docs__read` с `ref {"object":"project","id":"<id из ссылки>"}`, затем `ref {"object":"node","id":"<content.id>"}` с `container {"kind":"project","id":"<id>"}`, **без payload**.
2. Полный текст грамматики в сообщении. Он важнее краткой грамматики из документа.
3. Zip с картинками `NN_name.png` (768×512), по одной к слову.

## Модули (план владельца)
| Модуль | Уроки | Тема |
|---|---|---|
| 1 | 1–10 | именное предложение |
| 2 | 11–20 | местоимения, двойственное и ломаное мн. ч., числа, لَيْسَ |
| 3 | 21–40 | глагол |
| 4 | 41–55 | |
| 5 | 56–70 | |
| 6 | 71–85 | |
| 7 | 86–100 | |
| 8 | 101–120 | |

Последний урок модуля обобщающий (`isReview: true`), образец — уроки 10 и 20. В обобщающем уроке нет отдельных предложений. Его тексты идут в `text` через абзац `## <название второго текста>`, перевод — в `textTranslation` с `## Текст 1. «…»` / `## Текст 2. «…»`. Тест в нём из 20 вопросов.

**Новый модуль** заводится так:
1. Создать файл `src/data/arabic/module-0M.json` с полями `{"module": "Модуль M. … (уроки X–Y)", "lessons": []}`.
2. Импортировать его в `src/seed/arabicLessons.ts` и добавить в `ARABIC_MODULES`.
3. Добавить в CI проверку названия модуля на странице курса.

Название модуля, переименованное владельцем в админке, код не трогает.

## Файлы урока N
1. `public/arabic/<name>.webp` — картинки, сжатые из png. Код: PIL `save(..., 'WEBP', quality=80, method=6)`. На сайте картинка появляется как media `arabic-<name>.webp`.
2. `src/data/arabic/module-0M.json` — урок дописывается в `lessons`. Собирать скриптом по образцу `build-lesson-21.example.py`, вручную не править.
3. `src/data/arabic/schemes/lesson-NN.ts`, где `export const lessonNN: LessonSchemes`. Плюс две строки в `schemes/index.ts`: import и `'arabskiy-urok-N': lessonNN`.
4. `src/migrations/<дата>_<время>_arabic_lesson_N.ts` — копия предыдущей миграции: `up` вызывает `installArabicLessons`, `down` пустой. В комментарии указать «Урок N … после урока N-1». Миграцию добавить в `src/migrations/index.ts`, import и запись в конец массива. Время в имени файла должно быть позже предыдущей миграции.
5. `.github/workflows/ci.yml`:
   - `/lessons/arabskiy-urok-N` добавить в **оба** списка страниц: в строку через пробел и в список в кавычках.
   - После проверок прошлого урока добавить две строки `check`:
     - `has`: «Урок N одним взглядом», `arabic-<картинка>`, `q-text`, фраза перевода текста, слово на странице словаря курса;
     - `hasnt`: пояснение к вопросу теста. Брать **только русский кусок без арабского**, потому что арабский на странице разбит тегами bdi.
6. `docs/tasks/050/SPEC.md` — раздел «Урок N «…» (дата)». В нём: что добавлено, что добавлено от себя, строка «Научный текст», миграция только добавляет.

## Данные урока (поля в JSON)
- Общие поля:
  - `slug: arabskiy-urok-N`;
  - `title` — без «Урок N.», номер сайт пишет сам;
  - `category: arabic`;
  - `passingScore: 80`;
  - `excerpt` — «После урока студент …».
- Поля `arabic`:
  - `stage: auto`, `isReview`;
  - `words`;
  - `grammarTitle`, `grammar` (текст gNN.txt), `grammarExamples: []`;
  - `sentences`: `{arabic, translation}`;
  - `textTitle` (арабское название), `text`;
  - `textTranslation` — абзацы через пустую строку;
  - `textSource` — русское название в «», можно с примечанием владельца к тексту;
  - `tasks`.
- `questions`: `{question, options:[{text}], correct: 1–4, explanation}`. Порядок вариантов — как в книге. `correct` берётся из ключей; в скрипте стоит `assert` на список ответов.
- **Слово-имя:** `word, translation, root, plural, tag (term|book|daily), theme?, note?, forms?, picture`.
- **Слово-глагол:** `word` = прошедшее время, а также `past`, `present`, `masdar`, `root`. В `forms` записать женский род (ذَهَبَتْ), чтобы его узнавала подсказка. В `note` писать «После глагола: إِلَى …» по колонке «Управление».
- **Слово без корня** попадает в таблицу «Служебные слова», картинки у него нет. Поэтому **у каждого слова с картинкой должен быть корень**. Если в документе корня нет, корень проставляется самостоятельно, и об этом пишется в SPEC.
- Примечания к словам из документа переносятся в `note` дословно.

## Грамматика (gNN.txt)
- Текст владельца переносится **дословно**. Разметка такая:
  - `## Заголовок` — раздел. Подзаголовки владельца становятся разделами, нумерацию «1.» можно убрать.
  - `арабский — перевод` — строка-пример.
  - `арабский — ||ответ||` — скрытый ответ.
  - `| a | b |` — строка таблицы, первая строка — шапка. Таблицы с табуляцией и «схемы в столбик» из сообщения превращать в такие таблицы.
- Если у владельца нет разделов **«## Проверьте себя»** (8–9 примеров со скрытыми ответами: перевод и разбор) и **«## Итоги урока»**, их нужно добавить. Пустые «Ответ» владельца заполняются.
- Ошибки исправлять и **сообщать владельцу**: неверная ссылка на номер урока, перевод, который расходится с ключами. Например, «Школа находится недалеко» было исправлено на «Школа не далеко».
- **Порядок слов** арабского и русского не путать (просьба владельца). В примерах арабский всегда стоит слева от тире.
- Названия падежей по-арабски — в скобках после русских: «именительный (رَفْعٌ)».

## Схемы (schemes/lesson-NN.ts)
- Нужна одна схема на каждый содержательный раздел, в стиле сайта. Образцы — `lesson-19.ts`, `lesson-21.ts`.
- Последняя схема называется «Урок N одним взглядом» и стоит на разделе «Закрепление изученного» или «Итоги урока».
- Блоки:
  - `formula` — части в порядке чтения арабского, первая часть — первое слово;
  - `compare` — 1–3 колонки с tone a/b/c;
  - `rules`.
- Правила (их проверяет `validate-schemes.py`):
  1. Ключ = заголовок `## …` буква в букву, включая «‘» и «?».
  2. Каждое `ar:` дословно встречается в тексте грамматики.
  3. `note` начинается с русской буквы.
- В подписях не ставить стрелку между арабскими словами: bidi переворачивает её. Лучше переформулировать, например «родительный падеж, вместо أَبُو».

## Упражнения и тест
- Упражнения — `kind: 'toAr'` (`prompt`, `material`, `answer`, `explanation`). Одно упражнение на выбор формы делается `kind: 'choice'`: по одному заданию на пункт, 3 варианта, `correct`. Так оно проверяется.
- `explanation` к каждому вопросу теста пишется самостоятельно, коротко. **Верные ответы никогда не уходят в браузер.** Тест проверяется сервером, CI это проверяет через `hasnt`.

## Научный текст (AGENTS.md)
- Арабские цитаты аятов и хадисов брать только из источника, хадис давать с номером. В учебных уроках их пока не было.
- Утверждения фикха из документа владельца указывать в SPEC и в отчёте как «из документа владельца, не сверено».

## Проверка до PR
Тестовая база в контейнере сессии — **не база владельца**:
```sh
service postgresql start
export DATABASE_URL=postgres://academy:academy@localhost:5432/academy2 PAYLOAD_SECRET=dev-only-secret-dev-only-secret-12345 PAYLOAD_DB_PUSH=false
python3 -I -X utf8 <скрипт сборки урока>    # СНАЧАЛА JSON, потом migrate, иначе миграция отметится без урока
python3 -I docs/arabic-lesson-tools/validate-schemes.py src/data/arabic/schemes/lesson-NN.ts gNN.txt
npm run migrate && npx tsc --noEmit
bash docs/arabic-lesson-tools/rebuild.sh
node docs/arabic-lesson-tools/check-lesson.cjs arabskiy-urok-N <ответы через запятую>   # тест 100 %, прокрутки вбок нет
node docs/arabic-lesson-tools/check-schemes.cjs arabskiy-urok-N 390                     # hscroll false
```
Если базы academy2 нет, её надо создать (`createdb`), выполнить `npm run migrate` и `npm run seed`. Seed запускать **только** в тестовую базу.

После этого посмотреть снимки словаря и 1–2 схем, а также прогнать `curl` по строкам `has`/`hasnt` из CI.

## PR, CI, слияние
1. Ветку задачи начинать от свежего `main`. Коммит: «Задача 50: урок N «…»» с подписями сессии.
2. Открыть PR в `main`:
   - в описании разделы «Что изменилось для владельца» и «Как проверить», включая ответы теста буквами;
   - назначить `dnsagaev-hub`;
   - подписаться на события PR.
3. Когда CI закончится, проверить:
   - `git fetch origin ci-logs && git show origin/ci-logs:status.txt` — `success` и ревизия PR;
   - в `ci.log` нет `ОШИБКИ` и `ГОРИЗОНТАЛЬНАЯ ПРОКРУТКА`;
   - строки урока есть.
4. Слить (squash). Владелец разрешил «обновлять после проверки автоматически всегда».

## Выкладка на Mac владельца (после каждого слияния, без вопроса)
Запустить `start_remote_control`. Параметры:
- `message_id` — сообщение владельца с уроком;
- папка `/Users/denisagaev/Documents/Projects/Academy`.

Поручение для этого запуска:
1. `git status` — нет ли изменений в коде. Если есть, ничего не трогать и сообщить.
2. Копия данных, как ярлык «Сделать копию данных»: `pg_dump` базы из контейнера `db` в `backups/baza-<дата-время>.sql` и копия media в `backups/`. Проверить, что дамп не пустой.
3. `git pull origin main`.
4. `docker compose up -d --build`. При ошибке повторить один раз.
5. В логах приложения миграция урока прошла без ошибок.
6. `curl`: страница урока и `/courses/stupen-1-01-arabic` отвечают 200, на странице есть нужный текст.

**Никогда:** `docker compose down -v`, удаление томов, `npm run seed`, сброс базы.

Когда придёт отчёт: `stop_remote_control`, затем короткое сообщение владельцу. В нём ссылка на урок `http://localhost:3000/lessons/arabskiy-urok-N`, имя файла копии, что исправлено и добавлено от себя, что не сверено, и «Жду урок N+1».

Если Mac не ответил, попросить владельца проверить, что Mac не спит и включён Remote Control.

## Озвучка
Словарь озвучивается **раз в модуль** (решение владельца 31.10.2026), а не после каждого урока. После последнего урока модуля надо сообщить координатору, что модуль M собран и слова нужно озвучить.

## Типичные ошибки (уже случались)
- Сначала migrate, потом JSON: миграция помечена выполненной, а урока нет. Нужно пересоздать тестовую базу.
- `hasnt` с арабским всегда проходит, потому что строка разбита bdi. Брать русскую часть пояснения.
- Пояснение к схеме начинается с арабского — нарушено правило 3 из раздела «Схемы».
- Стрелка между арабскими словами в подписи схемы перевёрнута.
- Ключ схемы не совпал с заголовком: схема молча пропадает (CI ловит «Урок N одним взглядом»).
- Слово с картинкой без корня ушло в «Служебные слова», картинка не показана.
- В скрипте проверки теста число вопросов задано жёстко (15): для обобщающего урока нужно 20.
- После `rebuild.sh` страница показывает урок без схем: работал старый сервер (процесс называется `next-server`, `pkill -f "node server.js"` его не останавливал). Исправлено в `rebuild.sh`; если сомневаетесь — `ps aux | grep next-server`.
