1. **Дефект: абзац перевода без номера молча теряется, файл при этом принимается.** `src/lib/docx.ts:75–79`: абзац
   с кириллицей, который не начинается с «N.» и не басмала, пропускается. Если владелец разобьёт длинный аят на два
   абзаца (Enter вместо Shift+Enter) или вставит пояснение отдельным абзацем, текст пропадёт без сообщения.
   Проверено: копия файла владельца с абзацем «ПРОДОЛЖЕНИЕ АЯТА 7 ВО ВТОРОМ АБЗАЦЕ» после аята 7 — 30 аятов, ошибок
   нет, текста абзаца в результате нет. Для научного текста тихая потеря хуже отказа. Предложение: после первого
   аята кириллический абзац без номера (кроме басмалы) — ошибка «Абзац без номера после аята 7: «…» — допишите его
   в абзац аята или удалите» (или, по решению владельца, приклеивать к предыдущему аяту). Заголовки до первого аята
   («СУРА 67», «Перевод, комментарий и редакция», «Дэни Сагаев») по-прежнему пропускать. — решение за исполнителем, до ворот 2.
   **Решение: исправлено.** Кириллический абзац без номера после первого аята — ошибка «В файле есть абзац перевода без номера …», файл не принимается; заголовки до первого аята пропускаются.
2. **Мелкое: комментарий, набранный в том же сохранении, что и загрузка нового файла, теряется.**

   аята 5 новый комментарий + новый файл → после сохранения комментарий только у аята 3; без файла тот же комментарий
   сохраняется. Предложение: брать комментарий сначала из `data.ayahs` (то, что в форме), потом из `originalDoc`.
   **Решение: исправлено.** Комментарии берутся сначала из формы этого же сохранения, потом из прежней записи.
3. **Мелкое: отклонённая повторная загрузка оставляет файл на диске.** После трёх отклонённых `PATCH` с файлом в
