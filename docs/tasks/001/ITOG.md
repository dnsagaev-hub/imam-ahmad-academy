## Решения по ходу
- **CI теперь запускается и на каждый PR в `main`** (раньше только на пуш в `main`). Без этого ветку задачи нечем
  проверить до слияния. Сохранение миграции в репозиторий по-прежнему только на `main`; журнал в `ci-logs` теперь
  пишут и прогоны PR, поэтому в `status.txt` добавлены ревизия ветки и её имя. Миграцию на PR CI больше
  не создаёт молча: без этого она попала бы в `main` после слияния без приёмки.
- Владелец код не читает: ворота 2 — PR с объяснением простыми словами и шагами проверки, слияние PR — его слово.
- Номер задачи — число по порядку, папка из трёх цифр, ветка `task/<номер>`.
- Задачи из «Открытых вопросов и идей» прежнего `CLAUDE.md` разнесены в `TASKS.md` (2–6) и `QUESTIONS.md` (1–5).
- Инструкции инструмента: для Claude Code это `CLAUDE.md` → `@AGENTS.md`, заполнены 19.10.2026.

## Передача: что сделать Claude Code на компьютере владельца
Подготовка шла вне компьютера владельца: ветка `task/001` закоммичена, но не отправлена на GitHub.
1. Прочитать `AGENTS.md` и `docs/tasks/README.md`. Убедиться, что папка — git-репозиторий на ветке `task/001`
   и `origin` указывает на `github.com/dnsagaev-hub/imam-ahmad-academy`. Подтянуть `main`: если в нём есть
   коммиты новее `fa9542e`, влить `main` в `task/001` и перенести в документы то, что эти коммиты меняют.
2. Проверить, что можно отправить ветку на GitHub и открыть PR: есть ли `gh` (`gh auth status`). Если `gh` нет —
   установить (`brew install gh`; если нет и Homebrew — спросить владельца, ставить ли его) и помочь владельцу войти
   (`gh auth login` через браузер), объясняя по шагам, куда нажать. Отправить ветку и открыть PR в `main`. Описание PR — простыми словами по разделу «Ворота 2» ниже.
3. Дождаться CI на PR. Зелёный = прогон успешен и в `ci.log` из `ci-logs` (ревизия ветки в `status.txt`) нет
   `ОШИБКИ` и `ГОРИЗОНТАЛЬНАЯ ПРОКРУТКА`. Красный — разобраться, это ворота до показа владельцу.
4. Записать результат прогона в «Проверки», закоммитить в ветку, показать владельцу ворота 2 и спросить «принять?».
5. По его слову слить PR (`gh pr merge --merge`) и сделать `git pull` в `main`. Отметку «принято» в этом файле
   и `[x]` в `TASKS.md` ставит следующая задача.
6. Предложить первую задачу (номер, уровень, почему она первая) и не брать её: следующая задача — новая сессия
   (в приложении Claude — новая сессия Code в этой же папке), с чтения `AGENTS.md`.

Данные владельца эта задача не трогает: тома Docker те же при любой папке (имя проекта задано в `docker-compose.yml`),
пересобирать локальную версию не нужно.
