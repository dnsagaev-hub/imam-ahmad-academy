## Мутации приёмщика (рассуждением по коду)
| Что сломано | Какой тест покраснел и почему | Вывод |
|---|---|---|
| Нет правила `.tp:hover` | desk «наведение открывает» → ОШИБКИ | ловится |
| Нет `e.preventDefault()` | phone «нажатие открывает, страница та же» → ОШИБКИ (ушли на `/prayer-times`) | ловится |
| Нет закрытия по нажатию мимо | phone «нажатие мимо закрывает» → ОШИБКИ | ловится |
| Расписание видно всегда | «закрыто сначала», «курсор ушёл — закрыто» → ОШИБКИ | ловится |
| Нет класса `topbar-prayer` у кнопки | до исправления — исключение без «ОШИБКИ», шаг с `continue-on-error` оставался зелёным; после — `try/catch` пишет «расписание намазов: ОШИБКИ» | ловится после исправления |
| Нет мостика `.tp-pop::before` | в CI не проверяется — только ручная проверка «курсор на расписании — открыто» | дыра, принята |

## Замечания приёмки и решения
- Esc не закрывал расписание, открытое наведением или Tab → исправлено: класс `dismissed` до ухода курсора или фокуса.
- Исключение в проверке CI терялось → исправлено: `try/catch` с «ОШИБКИ», ожидание 5 с.
- Неразрывный пробел-заглушка в дате заменился обычным (строка схлопывалась до загрузки) → возвращён.
- Мостик над расписанием уже кнопки с длинным городом → расширен влево.
- `role="dialog"` и `aria-expanded` давали неверное состояние на компьютере → убраны, осталась `aria-label`.
- Время считалось дважды (два таймера) → считается один раз в `TopBar`.
- На `/prayer-times` ссылка внутри расписания не закрывала его на телефоне → закрывает.
- `npm run lint`: новых ошибок нет (закрытие при переходе на другую страницу сделано без `setState` в эффекте);
  прежние ошибки `react-hooks/set-state-in-effect` в `useNow` и других файлах — как были.
