## Владелец и общение

## Что это за сайт

Онлайн-школа ханбалитского фикха «Академия имама Ахмада»: курсы по 4 ступеням, уроки (видео, аудио, текст
с арабским оригиналом и переводом), тест после каждого урока, шкала успеха, статьи и разборы вопросов,
библиотека книг, время намазов, контакты. Аудитория — в основном Россия.

Девиз в шапке: «مع المحبرة إلى المقبرة» — «С пером — до могилы» (имам Ахмад ибн Ханбаль), без огласовок.

### Разделы (меню)
О сайте · Курсы · Текстовые уроки · Аудиоуроки · Видеоуроки · Статьи и вопросы · Библиотека · Связаться с нами.
Вверху — полоса с григорианской и хиджрийской датой и ближайшим намазом; кнопка «Мой прогресс».

### Ключевые решения
- **Регистрации нет** (флаг `NEXT_PUBLIC_REGISTRATION_ENABLED=false`). Сайт не собирает персональные данные:
  прогресс ученика хранится в браузере (localStorage), его можно выгрузить/загрузить файлом на `/progress`.
  Код для режима с регистрацией сохранён (кабинет, вход, серверная проверка тестов) — включается флагом.
- **Учебная программа — 4 ступени, 44 дисциплины** (сводная редакция от 17.10.2026):
  I Тамхиди (подготовительная, 10) · II Мубтади (начальная, 10) · III Мутавассит (средняя, 13) ·
  IV Мутакаддим (продвинутая, 11). Данные — `src/seed/program.ts`. Значения ступеней: `prep | beginner | intermediate | advanced`.
  Шкала успеха «Мой прогресс» — те же 4 уровня (`STUDENT_LEVELS`, `studentLevel()` в `src/lib/learning.ts`).
- Курс = одна дисциплина ступени (поля: ступень, номер, дисциплина, статус «утверждено / рабочий выбор /
  пособие в разработке», объём изучения, учебники из библиотеки). Курс → модули → уроки. Пока у курса нет
  уроков, он показан как «Готовится».
- Правильные ответы тестов **никогда не отправляются в браузер** (поле `correct` читает только админ,
  проверка — серверными действиями `checkAnswer`/`submitQuiz`).
- Цвета: бело-зелёная гамма из эмблемы (`--navy #003d2c`, `--royal #00704f`, `--gold #00a07a` и т. д. в `styles.css`).
  Шрифты локальные (пакеты `@fontsource`): Cormorant Garamond, Manrope, Amiri. Google Fonts не использовать
  (из России бывает недоступен, и он ломал сборку).
- Время намазов считается в браузере (порт PrayTimes.org, аср по ханбалитскому — коэффициент 1);
  хиджра — `Intl` (Umm al-Qura) с поправкой ±2 дня из настроек.
- Видео: в уроке хранится ссылка; `src/lib/video.ts` (`toEmbedUrl`) превращает обычные ссылки VK Видео,
  Rutube, YouTube, Kinescope в ссылки для встраивания. Аудио — MP3, загрузка до 300 МБ.
- Библиотека: книга = матн/шарх/хашия/справочник/перевод/пособие, ступень, «опорная книга мазхаба»,
  связь «шарх → матн», основной PDF + список «Тома и файлы» (много PDF), ссылки «Читать онлайн».
  «Путь изучения фикха» строится из книг раздела «Фикх» по ступеням.

## Научные материалы — строгие правила

Содержание уроков и статей — религиозное. Нельзя выдумывать:
- Арабские цитаты — **только из источника** (оцифровки «аль-Мактаба аш-Шамиля», OpenITI, turath.io),
  никогда по памяти. Каждую цитату сверять с текстом книги.
- Основное мнение мазхаба (му‘тамад) — по «Шарх Мунтаха аль-Ирадат», «Кашшаф аль-Кына‘» (аль-Бухути),
  «Матолиб Ули ан-Нуха». Если «аль-Мунтаха» и «аль-Икна‘» расходятся — приводить оба мнения.
  Выборы отдельных учёных (например, Ибн Таймии) помечать как «другое мнение», а не как мазхаб.
- Хадисы — указывать «сверить на Dorar.net», если оценка не проверена.
- Сайт объясняет книги мазхаба, **а не выносит личные фетвы** — это сказано на страницах статей и контактов.
- Сомнительное помечать блоком «Пометка» с видом «Сверить с источником».

## Технологии

- **Next.js 16** (App Router, Turbopack) + **Payload CMS 3.82** (админка на `/admin`) + **PostgreSQL**.
- React 19, TypeScript 6, Node 24. Хранилище файлов — S3 (если заданы `S3_*`), иначе папка `media/`.
- Сборка: `output: 'standalone'`, `Dockerfile` (многоэтапный). На этапе сборки в Dockerfile подставляются
  временные `PAYLOAD_SECRET`/`DATABASE_URL`; все страницы `force-dynamic`, поэтому база при сборке не нужна.
- Таблицы базы создаются **миграциями** (`src/migrations`, `prodMigrations` — применяются при запуске сайта).

## Как работать

### Локальная разработка
- Владелец запускает сайт ярлыком «Запустить сайт (Mac).command» → `docker compose up -d --build` →
  http://localhost:3000, админка http://localhost:3000/admin.
- Для разработки с горячей перезагрузкой: база из compose (`docker compose up -d db`), затем
  `DATABASE_URL=postgres://academy:academy@localhost:5432/academy` — но порт базы в compose наружу **не открыт**;
  если нужен `npm run dev`, добавь `ports: ['5432:5432']` к сервису `db` (осторожно: это та же база с данными владельца).
- Команды: `npm run dev`, `npm run build`, `npx tsc --noEmit`, `npm run migrate`, `npm run migrate:create -- <имя>`,
  `npm run seed` (демо-наполнение, только для пустой тестовой базы).

### ⚠️ Данные владельца — не потерять
- Владелец **уже наполняет локальную версию** материалами. Данные лежат в Docker-томах проекта
  `imam-ahmad-academy` (`db-data`, `media`), не в папке с кодом.
- **Никогда** не выполняй `docker compose down -v`, не удаляй тома, не сбрасывай базу без явной просьбы.
- Перед любыми изменениями, затрагивающими базу, предложи запустить «Сделать копию данных» (pg_dump + папка media
  в `backups/`).
- Стартовое наполнение (`SEED_STARTER=true`) выполняется **один раз**: после этого в настройках ставится
  скрытый флаг `starterSeeded`, и удалённые/изменённые материалы не восстанавливаются.

### Миграции базы — правила
- Любое изменение полей коллекций требует новой миграции: `npm run migrate:create -- <имя>`.
- Делай изменения **только добавляющими**: новое поле/таблица. Не переименовывай и не удаляй поля —
  drizzle задаёт интерактивный вопрос «создать или переименовать столбец», а старые данные могут пропасть.
  Пример: одиночное поле курса `book` заменено на `books`, но `book` оставлено скрытым.
- Новое значение в select (enum) нельзя сразу делать значением по умолчанию в той же миграции
  (Postgres: «unsafe use of new enum value»).
- Проверяй, что в `up` миграции нет `DROP`.
- CI сам создаёт миграцию, если схема изменилась, и коммитит её вместе с `package-lock.json`
  (коммит «Автоматически: … [skip ci]») — после пуша делай `git pull`.

### Проверка (CI)
- Каждый пуш в `main` запускает `.github/workflows/ci.yml`. Журнал и снимки страниц (компьютер/телефон)
  сохраняются в ветку **`ci-logs`** (`ci.log`, `shots/*.png`, `site-preview.zip` — статическая копия сайта).
- Перед тем как сказать «готово», убедись, что CI зелёный и в `ci.log` нет `ОШИБКИ`/`ГОРИЗОНТАЛЬНАЯ ПРОКРУТКА`.

### Обновление локальной версии у владельца
Владелец распаковывает новую версию в новую папку (или делает `git pull`), запускает «Сделать копию данных»,
затем «Запустить сайт». Миграции применяются при старте.

## Размещение (ещё не сделано)

Выбран **Timeweb Cloud**: App Platform (сборка из GitHub по Dockerfile, автодеплой), облачная PostgreSQL
в той же приватной сети, S3-хранилище (`S3_ENDPOINT=https://s3.twcstorage.ru`, `S3_REGION=ru-1`).
Переменные: `DATABASE_URL`, `PAYLOAD_SECRET` (сгенерировать новый: `openssl rand -hex 32`),
`NEXT_PUBLIC_SERVER_URL`, `NEXT_PUBLIC_REGISTRATION_ENABLED=false`, `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`,
`S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`.
- **Не ставить** `SEED_STARTER=true` на хостинге, если будем переносить локальную базу владельца.
- После первого запуска сразу создать администратора на `/admin` (первый вошедший становится админом).

**Перенос локальных данных на хостинг (задача на будущее):** `pg_dump` локальной базы → восстановить в базу
Timeweb (до первого запуска сайта или в пустую базу); файлы из тома `media` загрузить в S3-бакет
(Payload storage-s3 хранит файлы по имени `filename` в корне бакета — проверить префикс перед загрузкой).
Наполнять только одну версию: локальную до переноса, хостинг — после.
